【问题2】yfinance 频繁限速 (Rate Limit) ⚠️
  现象: 连续调用时报 YFRateLimitError: Too Many Requests

【问题3】缓存结构问题 ⚠️
  现象: 缓存返回 dict 格式 {"symbol": ..., "dates": [], "close": []}
  但 analysis.py 的 load_data() 依赖 raw["gold"]["close"] 为 list
  当 yfinance 失败时，缓存了空 list，后续分析全部空转
  建议: 在缓存写入前校验数据非空

    # 在 write_cache 之前添加:
    if not raw_data["gold"]["close"]:
        print("⚠️ 数据为空，不写入缓存")
        return result  # 返回空结构但不缓存

二、analysis.py — 相关性分析模块
===========================================================

【问题1】需要调用方预先构建 gold_ret/wti_ret 列 ⚠️
  现象: pearson_corr/spearman_corr/kendall_corr 等函数
        直接访问 df["gold_ret"]，但如果用户直接传入原始 DataFrame 会 KeyError
  分析: load_data() 会自动添加收益率列，所以通过 load_data 调用没问题
        但如果用户直接调用 pearson_corr(df) 就会报错
  建议: 在各函数开头添加保护:

    def pearson_corr(df: pd.DataFrame) -> dict:
        if "gold_ret" not in df.columns:
            df = df.copy()
            df["gold_ret"] = df["gold"].pct_change()
            df["wti_ret"] = df["wti"].pct_change()
            df = df.dropna()
        r, p = stats.pearsonr(df["gold_ret"], df["wti_ret"])
        ...

【问题2】statsmodels FutureWarning ⚠️
  现象: grangercausalitytests 抛出 FutureWarning: verbose is deprecated
  修复: 调用时加 verbose=False 即可（实际代码已加，是 statsmodels 自身警告）
  建议: 在文件顶部加 warnings.filterwarnings('ignore', category=FutureWarning)

【问题3】rolling_corr 趋势判断越界风险 ⚠️
  在 run_all() 中:
    rc.iloc[-window]
  当数据不足 window 条时，会取到前面 NaN 的位置
  建议: 添加保护

    trend_ref = rc.dropna().iloc[0] if len(rc.dropna()) > 0 else 0
    print(f"趋势: {'上升↗' if rc.iloc[-1] > trend_ref else ...}")
