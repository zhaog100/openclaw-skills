石油黄金报告模板优化方案 v1.0
===============================
日期：2026-04-16
作者：小米椒 🌶️‍🔥


一、优化背景
------------

旧版 report_text.py (v1.0) 存在以下问题：
1. 报告内容单一，只有仪表盘评分+宏观信号灯，缺少行情数据和技术详解
2. 整条消息过长，QQ会截断导致排版混乱
3. 宏观信号灯和操作建议混在一起，不够直观
4. 缺少30日区间、年初至今、均线对比等关键数据


二、新版模板结构（拆分双消息）
------------------------------

【PART 1：行情 + 仪表盘 + 技术详解】

标题 + 关键拐点
  - 日期、消费者信心提示

📊 行情（最新收盘）
  - 黄金：价格/日涨跌/30日涨跌/年初至今/30日区间
  - 原油：价格/日涨跌/30日涨跌/年初至今/30日区间
  - 数据来源：akshare（akshare替代yfinance，腾讯云IP不被封）

🎯 仪表盘
  - 沪金：评分/进度条/技术面/宏观面/信号灯
  - 沪油：评分/进度条/技术面/宏观面/信号灯
  - 地缘风险：评分/进度条
  - 数据来源：advisor._analyze_instrument() (90日周期)

📈 技术详解
  - 均线对比（5日 vs 10日，判断企稳/偏空）
  - MACD金叉/死叉
  - OBV量价背离（底背离✅/顶背离⚠️）
  - RSI超买超卖
  - 支撑位/阻力位
  - KDJ超买超卖区


【PART 2：宏观信号灯 + 操作建议】

💡 宏观信号灯 & 操作建议

宏观信号灯（固定格式，不改）：
  信心:57 悲极 | VIX:19.2 平静|利差:0.52 正常| 信用:2.94 宽松

操作建议（根据评分动态生成）：
  🥇 黄金 [建议] [理由]
  🛢️ 原油 [建议] [理由]
  组合建议：黄金:原油比例

结论 + 免责声明


三、评分与建议映射规则
----------------------

| 评分区间 | 判定 | Emoji | 黄金建议 | 原油建议 |
|----------|------|-------|----------|----------|
| ≥75 | 建议买入 | 🟢 | 逢低买入 | 可入场 |
| 60-74 | 可考虑 | 🟡 | 分批建仓 | 关注机会 |
| 40-59 | 观望 | ⚪ | 观望偏多/等信号 | 观望等企稳 |
| 25-39 | 回避 | 🟠 | 暂不操作 | 回避 |
| <25 | 强烈回避 | 🔴 | 不建议 | 强烈回避 |

组合比例规则：
  - 黄金评分 > 原油评分 → 7:3（黄金偏防守）
  - 两者差距 < 20 → 5:5（均衡配置）
  - 原油评分 >> 黄金评分 → 3:7（原油偏强）


四、技术面详解生成规则
----------------------

从 _analyze_instrument() 返回值中提取：

| 字段 | 用途 | 输出示例 |
|------|------|----------|
| macd.signal | MACD信号 | MACD金叉 / MACD死叉 |
| obv.divergence | 量价背离 | 量价底背离✅ / 量价顶背离⚠️ |
| rsi | RSI指标 | RSI=62超买 / RSI=28超卖 |
| sr.support1/resistance1 | 支撑阻力 | 支撑¥1000 阻力¥1100 |
| kdj.signal | KDJ信号 | KDJ超卖区 |

均线判断（从 fetch_data 原始数据计算）：
  - MA5 > MA10 → "企稳"
  - MA5 < MA10 → "偏空"

60日相关性（从 fetch_data 原始数据计算）：
  - |r| < 0.3 → "分化"
  - r ≥ 0.3 → "正相关"
  - r < -0.3 → "负相关"


五、数据获取流程
----------------

1. fetch_data() → 获取黄金/原油期货原始数据（akshare）
   - 1年历史数据（用于YTD、30日区间、均线、相关性）
   - 缓存5分钟，避免频繁请求

2. _analyze_instrument('沪金期货', period='90d', horizon=3)
   _analyze_instrument('沪油期货', period='90d', horizon=3)
   → 技术面分析（RSI/MACD/KDJ/Boll/ATR/OBV/支撑阻力/评分）

3. geopolitics.generate_geopolitical_section()
   → 地缘风险评分

4. 宏观信号灯
   → 当前为静态数据（信心:57 / VIX:19.2 / 利差:0.52 / 信用:2.94）
   → 后续可接入 FRED API 动态获取


六、代码改动清单
-----------------

文件：skills/oil-gold-correlation/scripts/report_text.py

改动前（v1.0）：
  - generate_report() → 单条完整报告
  - 只有仪表盘+宏观信号灯+结论
  - 无行情数据、无技术详解、无操作建议

  - generate_report() → 兼容旧接口，合并输出
  - 新增：行情数据（日/30日/YTD/区间）
  - 新增：技术详解（均线/MACD/OBV/RSI/支撑阻力）
  - 新增：操作建议（根据评分动态生成）
  - 新增：组合建议（根据评分比例动态生成）

新增依赖函数：
  - get_tech_detail() → 生成技术面详解文本
  - get_operation_advice() → 生成操作建议文本
  - generate_report_parts() → 拆分双消息


七、Cron 任务更新
-----------------

6个 oil-gold cron 任务的 message 统一更新为：

  运行脚本 python3 /root/.openclaw/workspace/skills/oil-gold-correlation/scripts/report_text.py，
  它会输出 PART 1 和 PART 2 两部分。
  先把 PART 1 的内容完整推送，再推送 PART 2 的内容。
  推送时去掉 === PART X === 分隔符和markdown星号。

涉及任务：
  - oil-gold-daily (10:00 早盘)
  - oil-gold-daily-bot2 (10:00 早盘)
  - oil-gold-nightly (15:30 日盘收盘)
  - oil-gold-nightly-bot2 (15:30 日盘收盘)
  - oil-gold-us-open (23:00 美盘开盘)
  - oil-gold-us-open-bot2 (23:00 美盘开盘)


八、已知限制与后续优化
----------------------

1. 拆两条消息依赖 prompt 指导 agent 分开发送
   → 更稳定的方案：脚本输出两个文件，cron 分别读取推送
   → 需要小米辣修改 cron 机制支持多文件推送

2. 宏观信号灯当前为静态数据
   → 后续可接入 FRED API 动态获取消费者信心/VIX/利差/信用

3. 操作建议的"理由"部分目前是规则生成的简短文本
   → 后续可让模型根据当天行情补充更详细的理由

4. 技术详解是单行文本，信息密度高但可能不够直观
   → 后续可考虑生成图片版报告
