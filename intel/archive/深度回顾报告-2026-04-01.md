### 1. 阿里云百炼API配置实践 ⭐⭐⭐⭐
- **接口地址**: OpenAI兼容 `https://coding.dashscope.aliyuncs.com/v1`
- **环境变量**: `DASHSCOPE_API_KEY` 需要设置到 `~/.bashrc`
- **配额管理**: 本月配额用完会报 `insufficient_quota`，需要等待下月刷新
- **主力保持**: 继续使用 `zai/glm-5`（智谱GLM-5），百炼作为备用
- **备用方案**: 百炼qwen系列、GLM-4.7、GLM-5-turbo作为降级备选
- **切换原则**: 主力模型稳定运行时不随意切换，避免影响工作流
- **成本控制**: 百炼配额用完时自动降级，不影响主力模型使用
- **配置位置**: `~/.openclaw/openclaw.json` 中的 `agents.defaults.model`

### 2. GitHub Token轮换与安全规范 ⭐⭐⭐⭐⭐
- **Token失效**: GitHub Token（401错误）导致推送失败
- **轮换流程**: 生成新Token → 更新secrets/ → 更新Git remote → 测试推送
- **脱敏规范**: Token显示格式 `ghp_XXX***YYY`，禁止输出完整Token
- **文件存储**: 敏感数据只存 `secrets/` 目录，该目录不加入Git
- **教训**: 定期检查Token有效期，避免推送失败影响工作流

### 3. Git分支管理优化 ⭐⭐⭐⭐
- **分支统一**: 删除远程master分支，统一使用main分支
- **操作流程**: 切换到main → 合并master → 推送到远程 → 删除远程master
- **配置更新**: 设置main为默认推送分支，与GitHub标准对齐
- **远程仓库**: https://github.com/zhaog100/xiaomijiao-skills (main分支)
- **教训**: 分支命名应与平台标准对齐，避免混淆

### 4. Linux内存优化实践 ⭐⭐⭐⭐
- **swappiness**: 已设置为10（减少swap使用）
- **缓存清理**: `sync && echo 1 > /proc/sys/vm/drop_caches`
- **效果**: 释放170MB内存（326MB→496MB）
- **定期执行**: 建议在内存紧张时执行缓存清理
- **教训**: 2GB内存运行Gateway+青龙+Docker偏紧张，建议升级到4GB
