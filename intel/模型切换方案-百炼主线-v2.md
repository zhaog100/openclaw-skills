🔧 模型切换方案：百炼主线 v2（最终版）

### 问题回顾

百炼模型反复切回智谱，历经 bailian → modelstudio → qwen 三轮 provider 名切换。
根因不是单一问题，而是 **四层叠加**：

┌────┬──────────────────────────────────────────────────────────────────────┬──────────────────────────────────────────────────┐
│ 层 │ 问题                                                                 │ 影响                                             │
├────┼──────────────────────────────────────────────────────────────────────┼──────────────────────────────────────────────────┤
│ L1 │ Provider 名用 "bailian"（非 OpenClaw 内置名），Gateway 不认识        │ 自定义 provider → URL 构造逻辑缺失 → 404         │
├────┼──────────────────────────────────────────────────────────────────────┼──────────────────────────────────────────────────┤
│ L2 │ 手动编辑 JSON 文件配置 auth profile，OpenClaw 内部 URL 解析丢掉 /v1 │ coding.dashscope.aliyuncs.com/v1 被截为 origin   │
├────┼──────────────────────────────────────────────────────────────────────┼──────────────────────────────────────────────────┤
│ L3 │ Fallback 成功后 Gateway 自动写入 session override                    │ modelOverride=zai/glm-5 锁死会话，改配置不生效   │
├────┼──────────────────────────────────────────────────────────────────────┼──────────────────────────────────────────────────┤
│ L4 │ 404 后 auth profile 进入 cooldown，后续请求直接跳过                   │ 全部 bailian 模型标记不可用                       │
└────┴──────────────────────────────────────────────────────────────────────┴──────────────────────────────────────────────────┘

### 最终解决方案

#### 核心发现

1. **OpenClaw 内置 provider 名**：百炼 = `modelstudio`（不是 `bailian`）
2. **Gateway 内部映射**：`modelstudio` → `qwen`（日志中显示 provider=qwen）
3. **URL 构造 bug**：手动配置的 baseUrl 经 `new URL().origin` 处理后丢掉 `/v1` 路径
4. **正确姿势**：必须用 `openclaw models auth add` 官方命令注册

#### 正确配置步骤

```bash
# Step 1: 用官方命令注册百炼 auth profile
openclaw models auth add
# → 选 custom (type provider id)
# → Provider id: modelstudio
# → Profile id: default
# → Does this token expire? No
# → 粘贴 API Key

# Step 2: 重启 Gateway
systemctl restart openclaw-gateway

# Step 3: 更新 cron 任务 model
openclaw cron edit <job_id> --model "qwen/qwen3.5-plus"
```

#### 关键配置文件

| 文件 | 作用 | 注意事项 |
|------|------|----------|
| `openclaw.json` | 主配置 | `models.providers.modelstudio` 不需要手动配 baseUrl |
| `auth-profiles.json` | 存储 API Key | 由 `openclaw models auth add` 自动管理 |
| `auth-state.json` | cooldown 状态 | 出问题需手动清理 cooldownUntil 字段 |
| `models.json` | 模型定义 | 不需要自定义 qwen/modelstudio provider，内置已覆盖 |
| `sessions.json` | 会话 override | 改模型后需清理 modelOverride 字段 |

#### 当前配置状态

```
Provider: qwen (内部名，由 modelstudio 映射)
Auth Profile: modelstudio:default → qwen:default
BaseUrl: 内置 coding.dashscope.aliyuncs.com/v1（OpenClaw 自动处理）
Key: sk-sp-f7e6***（Coding Plan 专用）
Models: qwen3.5-plus, qwen3-max, qwen3-coder-next 等
Fallback: qwen/* → zai/* → longcat/*
```

### 注意事项

1. **改模型必须用官方命令**：`openclaw models auth add`，不要手动编辑 JSON
2. **Provider 名映射**：`modelstudio` = `qwen`（Gateway 内部用 qwen）
3. **Coding Plan baseUrl**：`coding.dashscope.aliyuncs.com/v1`（内置，不要手动配）
4. **改模型三件套**：清理 session override + 更新 cron model + 清理 auth-state cooldown
5. **key 前缀**：`sk-sp-` = Coding Plan 专用，不能用于标准 dashscope 地址

### 踩坑记录（不要重蹈覆辙）

| 错误操作 | 结果 | 正确做法 |
|----------|------|----------|
| 手动编辑 openclaw.json 加 apiKey | Gateway 不读这个字段 | 用 openclaw models auth add |
| 手动编辑 auth-profiles.json | URL 构造丢 /v1 → 404 | 用 openclaw models auth add |
