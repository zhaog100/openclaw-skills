百炼 Rate Limit 解决方案
==========================
日期：2026-04-16
作者：小米椒 🌶️‍🔥


一、什么是 Rate Limit
======================

Rate Limit = 请求速度太快被限制

百炼API短时间内收到太多请求（对话、cron任务、工具调用）
→ 服务器返回429错误（"你太快了，等一下"）
→ OpenClaw自动切换到备用模型（智谱）
→ 切换后锁定在智谱，不会自动切回百炼

就像手机流量套餐，用太快超了就会被限速。


二、为什么会被锁定
==================

OpenClaw的Fallback机制是单向的：
百炼 → 智谱 → LongCat，只能往前走，不能掉头

流程：
1. 百炼rate limit → 返回429
2. 尝试fallback链里的下一个模型
3. 百炼5个模型全部失败（同一个厂商一起限速）
4. 智谱成功 → Gateway把"当前用智谱"写到sessions.json
5. 下次对话读sessions.json → 发现"上次用智谱" → 继续用智谱
6. 即使百炼恢复了 → 还是智谱 → 锁死

关键：
- rate limit是临时的（等几分钟就恢复）
- 但Gateway把它当永久故障处理
- 所以锁死了不会自动切回


三、解决方案
============

model-guard.sh 定时守护脚本

路径：scripts/model-guard.sh
频率：每5分钟自动执行
日志：logs/model-guard.log

功能：
1. 清理 sessions.json 里所有session的override字段（11种）
   - modelOverride
   - providerOverride
   - authProfileOverride
   - authProfileOverrideSource
   - authProfileOverrideCompactionCount
   - modelOverrideSource
   - fallbackNoticeActiveModel
   - fallbackNoticeReason
   - fallbackNoticeSelectedModel
   - model
   - modelProvider

2. 清理 auth-state.json 里的错误记录
   - errorCount
   - failureCounts
   - lastFailureAt
   - cooldownUntil
   - cooldownReason

效果：
- 即使百炼被rate limit切到智谱，最多5分钟后自动切回百炼
- 不会锁死

五、Fallback链配置
====================

主力：bailian/qwen3.5-plus（百炼）

Fallback链（按顺序）：
 1. bailian/qwen3-max-2026-01-23
 2. bailian/qwen3-coder-next
 3. bailian/glm-5
 4. bailian/glm-4.7
 5. bailian/MiniMax-M2.5
 6. zai/glm-5.1
 7. zai/glm-5
 8. zai/glm-4.7
 9. zai/glm-4.7-flash
10. longcat/LongCat-Flash-Lite

说明：
- 百炼5个模型在前面，但同一厂商rate limit会全挂
- 智谱4个模型是第二梯队
- LongCat免费模型兜底


六、百炼配置要点
=================

1. baseUrl必须用Coding Plan专用地址
   coding.dashscope.aliyuncs.com/v1
   不是默认的 dashscope.aliyuncs.com

2. 8个模型必须全部配置
   qwen3.5-plus / qwen3-max-2026-01-23 / qwen3-coder-next
   qwen3-coder-plus / glm-5 / glm-4.7 / kimi-k2.5 / MiniMax-M2.5

3. API Key需要定期检查是否过期
   在阿里云百炼控制台查看


七、注意事项
=============

1. model-guard.sh每5分钟运行，不会影响正常使用
2. 日志在logs/model-guard.log，建议每月检查一次大小
3. 如果百炼Key本身失效（不是rate limit），需要手动更新Key
4. 改模型不只是改配置文件，必须同时清理session override + auth-state cooldown
