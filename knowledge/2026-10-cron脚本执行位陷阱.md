# cron 调用的 .sh 脚本丢失 +x 执行位 → exit 126

## 症状
cron 任务跑 .sh 报 "Permission denied"，exit code 126（不是命令错，是没执行位）

## 根因
改脚本时"临时文件重写 + mv 回去"（如补版权头/脱敏），重建后没保留原来的可执行位，
文件从 -rwxrwxr-x 变回 -rw-rw-r--（丢 +x）

## 修复
find skills -name "*.sh" -type f ! -perm -u+x | grep -vE "__pycache__|backup-" | xargs -r chmod +x
# 再用 cron 同法验证：
sh -lc "/path/to/脚本.sh"   # exit=0 修好，126 还差

## 教训（进 rules/experience.md 经验17）
改任何 cron 调用的 .sh，提交前必 bash -n + chmod +x 复核执行位，别只查内容
